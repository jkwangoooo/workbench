## 二、两个必须先处理的问题（不是新功能）

这两项不解决，后面加的页面越多、数据越不可挽回。

### 问题 1：全部数据只存在"这台电脑的这个浏览器"里

`localStorage` 没有任何导出/备份入口。清缓存、换浏览器、重装系统、换电脑 —— 一个学期的违纪、作业、成绩、听写记录**全部消失且无法恢复**。这比缺任何一个页面都严重，而且它本身就是一个纯本地功能。

### 问题 2：学生 ID 是按序号派生的，顺序一变历史记录就错位

`app/core/roster.js` 里 `id: local-8-${index + 1}` —— ID 由**种子文件里的排序**决定。而所有历史数据都以这个 ID 为外键：

- 作业反馈 `data['8:2026-09-14'][studentId]`
- 单元测试 `test.scores[studentId]`
- 听写成绩 `sheet.scores[studentId:columnId]`
- 目标分 `sheet.targets[studentId]`

只要有人往 `private-data/students.js` 里插一名学生、调一次顺序，**全班的历史成绩都会静默错位到隔壁同学名下**，而且不会有任何报错。这是静默数据污染，必须在上真实数据之前修掉。

### L1 · 违纪记录重构（已完成）

对齐 `legacy-cloud/docs/04-feedback-module.md` §3。

| 编号 | 任务 | 落点 |
| --- | --- | --- |
| L1-1 | 8 班全班名单一页铺开，**按学生一行**，不需要逐个点开弹窗 | `app/pages/violations.js` |
| L1-2 | 输入即置顶：有内容的学生自动排到最前，排序稳定不跳动 | 同上 + `app/domain/violations.js` 的 `orderStudents` |
| L1-3 | 统一批量保存：一次保存全班，只有点「保存」才落盘 | `diffDay`（纯函数）+ `app/main.js` 的 `saveViolations` |
| L1-4 | 清空即删除：把某学生内容清空并保存，该条记录移除 | `diffDay` 的 `removed` 分支 |
| L1-5 | 校验失败整批不落盘并给出定位 | 校验「日期非法」与「出现名单外的学生」；写入失败（存储写满）同样一字不落并提示先去导出备份 |

**验收**：50 人一页可连续录入；置顶顺序在刷新后保持稳定；清空后刷新不复活。

**实际结果**（均已通过）：

- `npm test` —— 44 项，其中新增 `local-app-violations`（9 项）、渲染测试 +3 项。
- `npm run verify:local` —— 21/21。真机验到：聚焦第 50 行的输入框 → 用真实键盘输入 → 该行到最上面且**焦点没被夺走** → 保存 → 刷新后仍置顶 → 键盘全选清空并保存 → 刷新不复活且该生回到花名册顺序。

**实现要点**

- 记录形态对齐需求 §6.1 的 `daily_violations`：`{ id, studentId, eventDate, content, lastRecordedAt, createdAt, updatedAt }`。旧形态 `{ date, student: 姓名, text }` 读取时自动认（姓名换稳定 ID），**不需要单独的一次性迁移脚本**；写入一律写新形态。
- 置顶用 CSS `order`，**不搬 DOM 节点**：把带焦点的行从文档里摘出去再插回来会让输入框丢焦点、光标跳回开头，打中文时会当场断线。
- 输入只在「从没内容变成有内容」那一刻算一次置顶，避免打字过程中行来回跳、也避免打断输入法候选词。

**与计划的偏差 / 需要确认的三点**

1. 「一屏铺开」按「全班 50 行同页、无需弹窗、列表内滚动」实现。50 行 × 32px ≈ 1800px，单列排不进一块屏幕；真要一屏可见只能改两列或把行高压到 20px 上下，都伤可读性，所以先按同页做。
2. 同一批一起保存的记录时间戳相同，刷新后同批内部回落为花名册顺序（需求 §3.3 的 `last_recorded_at` 倒序在这里同样并列）；会话内保持你的编辑先后。并列规则写在 `orderStudents` 里，结果始终确定。
3. 删掉了两条旧路径：弹窗式「新增违纪记录」（与「每人每天只保留一段」冲突，会造出同学生同日多条）与历史总表（需求 §3.1 明确不要汇总统计，改为按日期翻）。看板「快捷记录」的入口改成直接跳到违纪页。**代价是学生个人的违纪历史暂时没有入口**，如需保留建议并进 L3 面谈或 L6 数据体检。

### L2 · 作业反馈重构（已完成）

对齐 `legacy-cloud/docs/04-feedback-module.md` §4。

| 编号 | 任务 | 落点 |
| --- | --- | --- |
| L2-1 | 每班每天**固定第 1 / 2 / 3 条**作业，各自独立 | `app/pages/homework.js` 三条 `slotRow` |
| L2-2 | 状态四档：优 / 良 / 差 / **不交** | `app/domain/homework.js` 的 `HOMEWORK_RATINGS` |
| L2-3 | 备注恒在，不因状态变化而隐藏 | 反馈表每行 `data-homework-note` 始终渲染 |
| L2-4 | 逐条独立保存（现在是一次保存全班）→ 实为「选中哪条保存哪条」 | `planSave` 纯函数 + `saveHomework` |
| L2-5 | 清空某条已反馈作业需二次确认，确认后级联删除该条全部学生状态 | `planSave` 返回 `needsConfirm` + `confirmDeleteHomework` |

**验收**：三条作业互不影响；任一条清空后二次确认，该条学生状态全部消失且其余两条不受影响。

**实际结果**（均已通过）：

- `npm test` —— **62 项**（L1 基线 50 + 新增 `local-app-homework` 12 项），其中新增覆盖：旧形态孤立反馈、v2 归一化幂等、首次保存默认优、改内容不重置反馈、三条互不影响、空作业不落盘、清空二次确认+级联删、非法状态整批不落盘、草稿默认优、反馈条数统计；渲染测试 +5 项（固定三条、保存两张表、互不影响+二次确认、未保存切页确认、旧版不丢）；备份迁移测 +1（v2 两张表形态迁移）。
- `npm run verify:local` —— **28/28**。真机新增 9 项 L2 验收：三条固定作业行 → 填内容 → 选中展开全班反馈表（默认优）→ 改状态/备注 → 保存写入 v2 两张表（tasks + feedback）→ 刷新读回 → 清空弹二次确认 → 确认级联删 → 其余不受影响。

**实现要点**

- 存储形态从「两层键嵌套 `{班级:日期}: {studentId: {rating,note}}`」升级为 **v2 归一化两张表**：`{ version: 2, tasks: [...], feedback: [...] }`，对齐需求 §6.2 `daily_homework` 与 §6.3 `homework_feedback`。
- **确定性 ID**：`taskIdOf = homework-${class}-${date}-${slot}`，`feedbackIdOf = ${homeworkId}|${studentId}`。元组本身就是唯一约束键，确定性 ID 让归一化天然幂等、不造幽灵记录（与 violations 用随机 `uid()` 不同）。
- 纯函数事务 `planSave`（对齐 violations 的 `diffDay`）：返回 `tasks/feedback/problems/needsConfirm/deleted/summary`，不改入参；校验不过整批不落盘。空内容+有反馈→返回 `needsConfirm`；`confirm:true`→级联删。
- 旧形态读取为"孤立反馈"（orphan），带 `legacy:true` 标记，保留不丢，页面提示条数。新写一律 v2。
- 共享未保存守卫 `pendingLeave()`（违纪+作业共用），弹窗文案通用化。
- 局部补丁 `refreshHomeworkUi`：打字时只换反馈面板 innerHTML 与状态牌，不动"作业内容"输入框（避免丢焦点，沿用 L1 教训）。

**与计划的偏差**

1. 保存按钮文案定为「保存本条作业反馈」而非「保存作业」，更准确表达语义——只保存当前选中的那一条作业及其反馈，不是全班一起。
2. 「逐条独立保存」的实现是选中哪条就保存哪条（而非三条分别各一个按钮），与 UI 三行布局一致——点哪行的区域/按钮就操作哪条。

## 四、每个新功能必须遵守的约束（为将来上云铺路）

即使本轮不碰云端，也按这些约束写，之后迁云不用重写业务逻辑：

5. **依赖方向不破**：`core` → `domain`/`io` → `pages` → `ui` → `main`，`npm run check` 会拦。
6. **每个阶段补测试**：纯逻辑进 `tests/unit/local-app-domain.test.mjs`；页面渲染进 `tests/unit/local-app-render.test.mjs`。
