# 每日工作安排模块实施文档

> 状态：需求已确认，等待实施  
> 一级模块：每日工作安排  
> 子模块：课表、每日待办  
> 适用班级：2025级7班、2025级8班；个人教师课表  
> 本文不包含：每周实际课表、单双周课表、待办优先级、分类、截止时间和提醒

## 1. 目标和边界

本模块管理固定周课表、按日期的临时调课和按日期的每日待办。三个子域必须独立存储和独立写入：

- 课表只负责课程安排。
- 临时调课只覆盖指定日期、指定课表、指定时段的课程安排。
- 待办只负责事项和完成状态，不得修改课表。

首页可只读汇合“今天的三张课表”和“今日待办”，但首页不得直接编辑任何课表。

## 2. 课表

### 2.1 课表范围

维护三张独立的固定周课表，均只覆盖周一至周五：

1. 2025级7班课表。
2. 2025级8班课表。
3. 我的课表。

课表格子只保存课程名称，不保存任课教师、班级、教室、备注或其他扩展字段。

### 2.2 时段

班级课表（7班、8班）每日时段按以下顺序固定：

1. 早读
2. 第一节
3. 第二节
4. 第三节
5. 第四节
6. 午休
7. 第五节
8. 第六节
9. 第七节
10. 第八节
11. 课辅A组
12. 课辅B组
13. 课辅C组

我的课表每日时段按以下顺序固定：

1. 早读
2. 第一节
3. 第二节
4. 第三节
5. 第四节
6. 午休
7. 第五节
8. 第六节
9. 第七节
10. 第八节
11. 课辅

时段是受控枚举，不允许在页面中新增、删除或修改名称，以免三张课表结构错位。

### 2.3 页面结构

课表页面使用三个独立标签页：

- 2025级7班课表
- 2025级8班课表
- 我的课表

每个标签页内部再切换：

- 固定课表
- 临时调课

当前标签页只读取和保存自己的数据。切换标签页前若有未保存修改，必须提示；不自动保存。

### 2.4 固定课表维护

- 始终显示周一至周五的固定周课表，不提供周次历史浏览。
- 在网页表格中直接编辑多个格子。
- 每格使用“常用课程下拉 + 自由输入”。下拉仅为输入辅助，不强制课程名称必须来自字典。
- 点击“保存当前课表”后，一次性保存当前标签页的全部变更。
- 保存失败时，数据库中原固定课表不变；页面保留未保存编辑内容并给出错误提示。
- 7班、8班和我的固定课表分别保存，互不影响。

### 2.5 临时调课

- 只允许选择周一至周五的具体日期；周六、周日不允许创建临时调整。
- 临时调课按“课表类型 + 具体日期 + 时段”独立保存。
- 打开临时调课时，页面保留周一至周五完整课表；只有所选日期对应的列可编辑，其余列只读。
- 固定课表作为当天底稿。未修改的格子继续显示固定内容，数据库不复制整张周课表。
- 临时内容只保存与固定课表不同的格子。
- 清空某个临时格子表示删除该时段的临时覆盖，恢复固定课表内容。
- 如需表示停课，在临时格中填写“停课”，而不是清空。
- 临时调整只影响该日期；日期过去后，不会改变固定周课表。
- 每张课表的临时调课独立保存，不能同步写入另外两张课表。

### 2.6 首页课表展示

每日待办首页只读展示：

- 今天我的课表
- 今天2025级7班课表
- 今天2025级8班课表

展示时优先使用当天临时调课；不存在临时调整时使用固定周课表。首页不得写入、编辑或删除课表。

## 3. 每日待办

### 3.1 待办字段

每个待办仅保存：

- 事项内容
- 计划日期，或无日期的“待确认”状态
- 完成状态
- 创建时间、完成时间和最后更新时间（仅内部管理）

不设截止时间、优先级、分类、子任务或附件。

### 3.2 页面结构

- 首页显示“今日待办”预览与完成勾选。
- “每日待办”页面默认显示今日。
- 页面可查看、添加和编辑从今天起未来14天的待办。
- 页面另设“待确认”区域。
- 完成事项保留在对应日期，显示已勾选状态；在未来14天编辑范围内可取消勾选。

### 3.3 待确认

待确认用于两类事项：

1. 创建时尚未决定哪天处理的事项。
2. 已过计划日期但仍未完成的事项。

待确认事项可通过拖拽安排到未来14天的某一天；同时必须提供“选择日期”操作，兼容安卓电脑的触控和键鼠使用。

安排日期后，待办从待确认移动到目标日期。一个待办同一时间只属于一个日期或待确认，不能复制到多天。

### 3.4 逾期整理

- 每次打开或刷新每日待办页面时，系统检查所有已过期且未完成的待办。
- 符合条件的待办自动移入待确认，计划日期清空。
- 已完成的历史待办保持原日期，不移动。
- 不使用每日零点定时服务；如当天未打开页面，下次打开时再整理。
- 整理函数必须幂等，多次调用不得产生重复待办或重复操作记录。

### 3.5 两周编辑窗口

- 可编辑范围为当天至未来第14天，含当天，共14个自然日。
- 过去日期不作为日常编辑区。
- 待确认可随时添加和重新安排到窗口内日期。
- 尝试将待办安排到过去日期或第15天之后时，页面必须阻止并提示；不得隐式改到其他日期。

## 4. 数据库结构与隔离

沿用 Supabase/PostgreSQL、`owner_id` 和 RLS。课表、临时调课和待办使用不同表，不以 JSON 混存。

### 4.1 课表表

#### `schedule_cells`

- `id uuid primary key`
- `owner_id uuid not null`
- `schedule_scope text not null`，仅允许 `class_7 / class_8 / teacher`
- `weekday smallint not null`，仅允许1至5
- `slot text not null`，必须符合对应 scope 的受控时段
- `course_name text not null`
- `updated_at timestamptz not null`
- 唯一约束：`(owner_id, schedule_scope, weekday, slot)`

#### `schedule_overrides`

- `id uuid primary key`
- `owner_id uuid not null`
- `schedule_scope text not null`，仅允许 `class_7 / class_8 / teacher`
- `schedule_date date not null`
- `slot text not null`
- `course_name text not null`
- `updated_at timestamptz not null`
- 唯一约束：`(owner_id, schedule_scope, schedule_date, slot)`
- 数据库检查：`extract(isodow from schedule_date)` 必须在1至5。

禁止在临时表中存整周副本、固定课表快照或其他 scope 的课程格子。

### 4.2 待办表

#### `todos`

- `id uuid primary key`
- `owner_id uuid not null`
- `content text not null`
- `planned_date date null`
- `status text not null`，仅允许 `pending / completed`
- `completed_at timestamptz null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

规则：`planned_date is null` 表示待确认；不得另存一份待确认列表，也不得为同一待办创建多个日期记录。

### 4.3 权限与原子性

- 所有表启用 RLS，所有读写必须满足 `auth.uid() = owner_id`。
- 浏览器端只使用 Supabase publishable/anon key，绝不使用 `service_role` 或 secret key。
- 固定课表保存只允许写入当前 `schedule_scope`。
- 临时调课保存只允许写入当前 `schedule_scope + selected_date`。
- 逾期整理只更新符合“未完成且计划日期早于今天”的当前用户待办，不能处理其他用户数据。
- 临时调课、固定课表和待办的保存函数各自独立，禁止一个操作事务写入另外两个域。

```text
src/modules/daily-work/

      overrideRepository.ts
    components/
      ScheduleTabs

  todos/

      todoRepository.ts
    components/
      TodayTodoList
      TwoWeekPlanner
      UnscheduledInbox
  dashboard/
    TodaySchedulePreview
    TodayTodoPreview
  shared/
    date/
    auth/
    database/
```

规则：

- `schedule` 不得导入或写入 `todos` repository。
- `todos` 不得导入或写入任何课表 repository。
- `dashboard` 只能调用只读查询组合函数，不能直接写数据库。
- 临时调课的“有效课表”由纯函数计算：先读固定格子，再以同 scope、同日期、同时段的覆盖值替代。
- 页面组件不得直接拼接 Supabase 请求。
- 常用课程下拉是 UI 配置，不得改变已保存课程名称或强制迁移旧课程内容。
- 不在 localStorage 保存课表、临时调整、待办内容或未保存编辑；未保存编辑只保留在当前内存会话。

## 6. 实施顺序

1. 建立每日工作安排模块目录、scope 枚举和受控时段定义。
2. 新增或迁移固定课表、临时调课和待办表的数据库约束与 RLS。
3. 实现三张固定课表的独立标签页和整张保存。
4. 实现按具体日期的临时调课底稿、覆盖计算和单 scope 保存。
5. 实现首页三张今日只读课表预览。
6. 实现今日待办、未来14天计划和待确认区域。
7. 实现待确认拖拽和选择日期两种安排方式。
8. 实现打开页面时的幂等逾期整理。
9. 完成未保存提示、失败回滚、跨 scope 隔离和跨设备验收。

不得在本模块中引入课程规划、资源库、作业、听写、测试或备课工作流。

## 7. 验收标准

### 课表

- 7班、8班和我的课表均有独立固定课表和临时调课标签。
- 固定课表仅显示周一至周五，时段顺序与本文一致。
- 每格仅保存课程名称；可下拉选择或自由输入。
- 当前标签页保存不影响另外两张课表。
- 临时调课仅允许周一至周五具体日期。
- 临时页面显示完整周表，但仅选定日期列可编辑。
- 临时调整优先显示；清空临时内容恢复固定内容；填写“停课”明确表示停课。
- 首页只读展示今天三张有效课表，不提供编辑入口。

### 待办

- 默认显示今日待办，完成后仍保留在当天并可取消勾选。
- 可添加和编辑从今天起未来14天的待办。
- 可创建待确认事项，并通过拖拽或选择日期安排到未来14天。
- 过期未完成事项在打开或刷新页面时移入待确认；已完成历史事项不移动。
- 待办没有优先级、分类、截止时间、附件或重复副本。

### 隔离与安全

- 修改待办不会修改任何课表或临时调课。
- 修改固定课表或临时调课不会创建或完成待办。
- 临时调课不会改写固定课表。
- 7班、8班和我的课表数据按 scope 完全隔离。
- 不同用户无法读取或写入彼此的课表和待办。
- 保存失败不留下半张课表、半组临时调课或部分待办更新。

## 8. 暂不实施

- 周次或每周完整实际课表历史
- 双周课表
- 周六、周日固定课表或临时调课
- 教室、任课教师、课程备注
- 课表 Excel 导入
- 待办截止时间、优先级、分类、提醒、子任务、附件
- 待办重复规则和周期性待办
- 首页直接编辑课表
