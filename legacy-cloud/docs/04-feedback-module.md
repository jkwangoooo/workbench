# 反馈模块实施文档

> 状态：需求已确认，等待实施  
> 一级模块：反馈  
> 子模块：当日违纪、作业反馈、每周学生面谈  
> 适用班级：违纪仅2025级8班；作业反馈和每周学生面谈为2025级7班和2025级8班  
> 本文不包含：违纪人数统计、作业排名、作业 Excel 导入、作业名称、截止时间、优先级、面谈 PDF 导出、历史恢复

## 1. 文档目的

本文件是反馈模块的实施依据。三个子模块虽然从同一个一级入口进入，但必须拥有独立的领域模型、页面状态、repository、事务和数据库表。

任何违纪操作不得写入作业或面谈数据；任何作业操作不得写入违纪或面谈数据；任何面谈操作不得写入违纪或作业数据。学生姓名只作为页面显示，数据库记录使用学生内部 `student_id`。

## 2. 页面结构

“反馈”作为一级模块，包含三个独立标签页：

1. 当日违纪
2. 作业反馈
3. 每周学生面谈

进入反馈模块时默认显示“当日违纪”的今天记录。标签页切换不得带入另一个子模块的日期、班级、工作周、未保存草稿或筛选状态。

## 3. 当日违纪

### 3.1 业务范围

- 只服务2025级8班。
- 可选择任意历史日期进行补录和修改。
- 不显示今日违纪人数、历史日期人数或其他汇总统计。
- 每名学生每天只保留一段违纪文字。
- 不记录违纪类型、严重程度、时间、地点、附件或处理结果。

### 3.2 页面与编辑

- 默认打开当天日期，显示2025级8班全体学生。
- 每行显示学生姓名和一段违纪文字编辑框。
- 没有违纪记录的学生文字为空。
- 输入文字后，该学生立即移动到当前页面最上方；其余有记录学生按最近编辑时间排列，其余学生按8班花名册顺序排列。
- 点击“保存当天违纪”后统一提交当前日期的变化。
- 一天内可以多次打开、编辑和保存；后续保存只更新当天8班违纪，不覆盖其他日期。
- 离开页面、切换日期或切换标签页时，如有未保存文字，必须弹出提醒。

### 3.3 排序规则

排序只影响违纪页面的显示，不改变8班花名册的 `sort_order`：

1. 当前日期已有文字记录的学生优先。
2. 有记录学生按最后一次成功保存的编辑时间倒序排列。
3. 尚无记录的学生按花名册原始顺序排列。

编辑后立即置顶是当前会话内的临时显示状态；保存成功后写入 `last_recorded_at`，刷新页面仍按同一规则置顶。清空并删除记录后，学生回到花名册原始顺序。

### 3.4 清空与删除

- 将某名学生当天的违纪文字清空，视为删除该日期该学生的违纪记录。
- 保存前可在当前页面撤销清空；提交删除时必须与其他当天变化一起保存。
- 删除后该学生立即回到花名册原始排序。
- 删除只影响一个学生、一个日期，不影响其他日期、其他学生或作业反馈。
- 删除操作不需要保留历史版本。

### 3.5 保存失败

- 当天多名学生的新增、修改和删除作为一次保存提交。
- 任一条写入失败时，整批保存回滚，数据库保持保存前状态。
- 页面保留未保存编辑，并明确提示失败原因；不得显示“已保存”。

## 4. 作业反馈

### 4.1 业务范围

- 适用于2025级7班和2025级8班。
- 可选择任意历史日期补录和修改。
- 每个班级、每天固定有第1、2、3条作业记录。
- 每条只填写作业内容，不设置作业名称。
- 空白作业条目不允许进入反馈表。

### 4.2 页面流程

1. 选择班级：2025级7班或2025级8班。
2. 选择日期：允许任意历史日期。
3. 页面固定显示第1、2、3条作业内容输入框。
4. 选择其中一条已有内容的作业。
5. 显示该班全体学生的反馈表。
6. 每名学生默认状态为“优”，并固定显示备注栏。
7. 修改状态或备注后，点击“保存本条作业反馈”。

第一次打开某条作业反馈时初始化全班为“优”；之后再次打开必须读取已有记录，不能重新初始化或覆盖历史修改。

### 4.3 反馈选项

状态只有四种：

- `不交`
- `优`
- `良`
- `差`

每名学生的反馈明细包含：

- `student_id`
- `rating`
- `note`

备注栏始终存在，可以为空；空备注保存为空字符串，不使用 `null`。不增加其他状态、评分或等级。

### 4.4 作业记录独立性

- 第1、2、3条作业分别保存，反馈不会互相覆盖。
- 同一日期的三条作业可以分别填写、分别反馈、分别保存。
- 选择第2条作业时，页面只能读取和保存第2条及其反馈。
- 修改作业内容不会自动重置学生反馈。
- 7班和8班使用不同 `class_id`，查询和保存必须明确带班级条件。
- 其他日期、其他班级和其他作业编号的数据永远不参与当前保存。

### 4.5 清空作业及永久删除

如果某条作业已有学生反馈，将作业内容清空视为删除该条作业：

1. 系统检测该条作业已有反馈。
2. 弹出二次确认，并显示将删除的反馈人数。
3. 确认后在一个事务中永久删除该条作业及其全部学生反馈。
4. 第1、2、3条编号保留为空，可以重新填写新的作业内容。

取消确认则不改变内容和反馈。删除不影响同日其他作业、其他日期、另一班级或违纪数据。删除后不提供恢复功能。

如果某条作业尚未有反馈，清空内容只需普通保存确认，不产生反馈删除提示。

### 4.6 保存失败

- 作业内容变化和当前作业的学生反馈变化必须作为一个作业域事务提交。
- 任一学生反馈写入失败时，整次当前作业保存回滚。
- 保存失败不得影响第1、2、3条中的其他作业。
- 页面保留未保存修改，并明确提示失败原因。

## 5. 每周学生面谈

### 5.1 业务范围

- 适用于2025级7班和2025级8班。
- 一个工作周固定为周一至周五，以周一日期作为该周唯一标识。
- 可查看、补录和修改任意历史工作周。
- 每名学生每周只有一个“本周已面谈”勾选状态和一段备注。
- 新工作周所有学生默认未勾选、备注为空，不继承上周内容。
- 不提供PDF导出，不记录具体面谈日期。

### 5.2 页面与排序

- 先选择班级，再选择工作周；默认打开当前工作周。
- 页面显示当前班级全体有效学生、勾选框和备注输入框。
- 顶部显示当前班级本周进度：`已面谈人数 / 当前班级学生总数`。
- 未面谈学生排在最上方，已面谈学生排在下方；每组内按花名册 `sort_order` 排列。
- 取消勾选不会删除原备注；备注可以单独修改或清空。
- 进度只统计 `completed = true` 的当前班级、当前工作周记录，不与另一班级或其他反馈子模块合并。

### 5.3 保存与切换

- 点击“保存本周面谈”一次提交当前班级、本周全部勾选和备注变化。
- 支持同一工作周多次保存；任一写入失败时整批回滚，页面保留未保存内容并显示失败原因。
- 离开页面、切换班级、切换工作周或切换反馈标签页时，如有未保存修改，必须提示确认。
- 已保存的面谈记录只影响当前班级和当前工作周，不覆盖其他周、其他班级或违纪、作业反馈数据。

### 5.4 空记录处理

- 未勾选且备注为空的学生可不写入数据库，页面按默认未面谈显示。
- 已勾选或备注非空时保存一条面谈记录。
- 取消勾选但保留备注时，记录保留并显示为未面谈；清空备注后，如仍未勾选，可在事务中删除该空记录。

## 6. 数据库结构与隔离

沿用 Supabase/PostgreSQL、单用户 `owner_id` 和 RLS。不得把违纪文字和作业反馈塞入同一张通用记录表或 JSON 字段。

### 6.1 违纪表

#### `daily_violations`

- `id uuid primary key`
- `owner_id uuid not null`
- `class_id uuid not null`，只能引用2025级8班
- `student_id uuid not null`
- `event_date date not null`
- `content text not null`
- `last_recorded_at timestamptz not null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- 唯一约束：`(owner_id, class_id, student_id, event_date)`

数据库约束或事务函数必须验证：

- `student.class_id = class_id`。
- `owner_id` 在班级、学生和记录之间一致。
- `class_id` 是2025级8班。
- `content` 去除首尾空格后不能为空；清空操作应删除行，而不是写入空行。

### 6.2 每日作业表

#### `daily_homework`

- `id uuid primary key`
- `owner_id uuid not null`
- `class_id uuid not null`，只能引用2025级7班或2025级8班
- `homework_date date not null`
- `slot smallint not null`，仅允许1、2、3
- `content text not null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- 唯一约束：`(owner_id, class_id, homework_date, slot)`

### 6.3 作业反馈表

#### `homework_feedback`

- `id uuid primary key`
- `owner_id uuid not null`
- `homework_id uuid not null references daily_homework(id) on delete cascade`
- `student_id uuid not null`
- `rating text not null`，仅允许`不交 / 优 / 良 / 差`
- `note text not null default ''`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- 唯一约束：`(owner_id, homework_id, student_id)`

数据库约束或事务函数必须验证：

- `student.class_id = daily_homework.class_id`。
- `owner_id` 在作业、学生和反馈之间一致。
- 反馈状态属于四个受控值。
- 空作业不得创建反馈。

### 6.4 每周面谈表

#### `weekly_interviews`

- `id uuid primary key`
- `owner_id uuid not null`
- `class_id uuid not null`，只能引用2025级7班或2025级8班
- `student_id uuid not null`
- `week_start date not null`，必须是周一
- `completed boolean not null default false`
- `note text not null default ''`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- 唯一约束：`(owner_id, class_id, student_id, week_start)`

数据库约束或事务函数必须验证：

- `extract(isodow from week_start) = 1`。
- `student.class_id = class_id`。
- `owner_id` 在班级、学生和记录之间一致。
- `class_id` 只能是2025级7班或2025级8班。
- 进度统计只计算当前班级、当前 `week_start` 且 `completed = true` 的记录。

### 6.5 RLS 和事务

- 四张表全部启用 RLS，所有读写必须满足 `auth.uid() = owner_id`。
- 浏览器端只能使用 Supabase publishable/anon key，不使用 `service_role` 或 secret key。
- 违纪保存只能写入`daily_violations`。
- 作业内容保存只能写入`daily_homework`，当前作业反馈只能写入`homework_feedback`。
- 作业删除事务只能删除当前 `homework_id` 及其反馈，不能按日期删除整批记录。
- 面谈保存只能写入当前班级、当前 `week_start` 的 `weekly_interviews`，不得触碰违纪或作业表。
- 任何前端传入的班级或学生编号都必须在数据库事务中再次校验，防止绕过页面造成跨班级写入。

边界规则：

- `violations`、`homework`、`interviews` 三个子域不得互相导入对方的 repository、领域类型或组件。
- 页面组件不得直接拼接 Supabase 请求。
- 排序、状态校验和删除条件使用纯函数或 domain service，便于单元测试。
- 当前未保存草稿只保留在内存，不写入 `localStorage`。
- 学生目录只提供 `student_id + class_id + display_name + sort_order + active`，不暴露档案敏感字段。

## 8. 交互状态

三个子模块都使用明确的保存状态：

- `clean`：没有未保存修改。
- `dirty`：有未保存修改。
- `saving`：正在提交，禁止重复点击。
- `saved`：最近一次提交成功。
- `error`：提交失败，保留草稿。

离开当前日期、切换班级、切换工作周、切换标签页或刷新前，如果状态为`dirty`，必须提示未保存内容。成功保存后再允许切换，不自动丢弃草稿。

1. 建立反馈模块目录、类型和三个子域边界。
2. 新增违纪、每日作业、作业反馈和每周面谈表，设置 RLS、唯一约束和同班级校验。
3. 实现8班任意日期违纪列表、行内编辑、置顶排序和统一保存。
4. 实现清空违纪文字即删除并恢复原排序。
5. 实现7班/8班每日第1、2、3条作业记录。
6. 实现作业选择、反馈默认“优”、备注和统一保存。
7. 实现作业清空的二次确认与事务删除。
8. 实现未保存提醒、失败回滚和多次保存。

10. 完成跨日期、跨工作周、跨班级、跨作业编号和跨子模块隔离测试。

不得在本模块实施时顺带修改成绩、课表、待办、学生档案或资源库。

## 10. 验收标准

### 违纪

- 只显示2025级8班，可选择任意历史日期。
- 每名学生每天只有一段违纪文字。
- 输入后立即置顶；保存刷新后仍按最后成功编辑时间置顶。
- 无违纪记录学生保持花名册顺序。
- 清空文字即删除记录并恢复原排序。
- 页面不显示人数统计。
- 可一天多次保存，保存失败不产生部分写入。

### 作业

- 可选择7班或8班和任意历史日期。
- 每天固定显示第1、2、3条作业。
- 每条只填写作业内容，不设置名称。
- 空白作业不能进入反馈表。
- 每名学生默认“优”，可改为“不交、优、良、差”，并有备注栏。
- 第1、2、3条反馈互不覆盖。
- 修改作业内容不会重置已有反馈。
- 清空已有反馈的作业需二次确认，确认后永久删除该作业及其反馈。
- 可一天多次保存，离开前有未保存提醒。

### 每周学生面谈

- 可选择2025级7班或2025级8班，以及任意历史工作周。
- 工作周固定为周一至周五，新周不继承上周状态或备注。
- 每名学生有一个“本周已面谈”勾选框和一段备注。
- 未面谈学生排在最上方，组内按花名册顺序排列。
- 取消勾选不会删除备注；备注可以单独清空。
- 顶部正确显示当前班级的已面谈人数和学生总人数。
- 当前班级、本周全部修改一次保存，支持多次保存且失败整批回滚。
- 面谈记录不提供PDF导出。

### 隔离与安全

- 违纪更新不会改变作业内容或反馈。
- 作业更新不会改变违纪记录。
- 面谈更新不会改变违纪记录或作业内容、反馈。
- 7班作业不会读取或写入8班学生，反之亦然。
- 7班面谈不会读取或写入8班学生，反之亦然。
- 删除一条作业不会删除同日其他作业或其他日期记录。
- 数据库在绕过前端时仍拒绝跨用户、跨班级和跨学生引用。
- 未登录或会话过期时不得返回学生姓名、违纪文字、作业内容、反馈或备注。

## 11. 暂不实施

- 违纪人数统计或图表
- 违纪类型、等级、地点、时间和处理结果
- 作业名称、截止时间、优先级和分类
- 作业 Excel 导入
- 作业或违纪批量删除
- 历史版本和恢复
- 对外分享反馈记录
