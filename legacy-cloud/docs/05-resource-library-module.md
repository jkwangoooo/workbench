# 资源库模块实施文档

> 状态：需求已确认，等待实施  
> 一级模块：资源库  
> 子模块：常用网站、工作文件  
> 本文不包含：文件夹层级、标签体系、文件版本恢复、回收站、资源对外分享、大体积音视频管理

## 1. 文档目的

本文件是资源库模块的实施依据。常用网站和工作文件虽然从同一个一级入口进入，但必须拥有独立的领域模型、页面状态、repository、数据库表和存储策略。

网站记录不得写入文件记录；文件上传、覆盖或删除不得修改网站数据。所有资源只属于当前登录用户，不向其他用户或未登录访问者公开。

## 2. 页面结构

“资源库”作为一级模块，包含两个独立标签页：

1. 常用网站
2. 工作文件

标签页切换不得带入另一个子模块的搜索词、分类筛选、未保存编辑或上传草稿。默认进入“常用网站”标签页。

## 3. 常用网站

### 3.1 字段

每条网站记录包含：

- 网站名称（必填）
- 网址（必填，保存前校验为 `http` 或 `https` URL）
- 自定义分类（可为空）
- 备注（可为空）
- 是否置顶（默认否）

网站分类是普通文本，不预设固定选项。分类比较时去除首尾空格，避免产生看似相同的重复分类。

### 3.2 展示与操作

- 置顶网站排在列表上方；置顶组内按名称排列。
- 未置顶网站按名称排列。
- 点击网站在新的浏览器标签页打开，当前资源库页面保持不变。
- 支持新增、编辑、置顶/取消置顶和删除。
- 删除网站需要二次确认；确认后永久删除网站记录。
- 网站子模块不显示或读取工作文件字段。

## 4. 工作文件

### 4.1 支持范围

- 允许上传常见办公文件：`doc/docx`、`xls/xlsx`、`ppt/pptx`、`pdf`、常见图片和`txt`。
- 单个文件大小上限为50MB；超过限制的文件在上传前拒绝，不产生云端对象。
- 不把音频、视频作为常规资源范围；如未来需要，另行设计独立策略。

### 4.2 文件字段

数据库元数据包含：

- 原始文件名
- 自定义分类（可为空）
- MIME类型
- 文件大小（字节）
- 上传时间
- 存储对象路径

文件分类是普通文本，不预设固定选项。文件列表支持按文件名搜索和按分类筛选；筛选只作用于当前“工作文件”标签页。

### 4.3 上传流程

1. 选择一个自定义分类。
2. 一次选择一个或多个文件。
3. 显示待上传清单：文件名、类型、大小和目标分类。
4. 可从清单移除不想上传的文件。
5. 点击确认后开始上传；确认前不创建数据库记录或云端对象。
6. 每个文件独立显示“待上传、上传中、已上传、失败”状态。

批量中的某个文件失败不得回滚已经成功的其他文件；失败项保留在清单中，允许单独重试。批量上传只共享分类，不共享文件记录或错误状态。

### 4.4 同名覆盖

同一用户、同一自定义分类下出现相同文件名时，系统只对该重复文件弹出覆盖确认：

- 弹窗显示原文件的上传时间和新文件的大小。
- 未确认前保留原文件，其他非重复文件可以继续上传。
- 确认后先上传新对象并完成元数据校验，再替换数据库引用。
- 新对象和元数据提交失败时保留原文件。
- 替换成功后删除旧存储对象和旧元数据；旧文件永久删除，不提供版本恢复。

同名判断必须带上 `owner_id` 和规范化后的分类，不能误判其他用户或其他分类的文件。

### 4.5 预览、下载与维护

- PDF、图片和TXT提供网页预览。
- Word、Excel、PPT优先尝试网页预览；浏览器或转换服务不支持时显示明确提示并提供下载。
- 预览和下载使用短时有效的私有签名URL，不把对象路径或文件内容放入公开URL。
- 支持重命名和修改分类；修改分类时重新执行同名检测。
- 删除文件需要二次确认，确认后永久删除数据库元数据和存储对象，不提供回收站或恢复。

## 5. 数据库结构与存储隔离

沿用 Supabase/PostgreSQL、单用户 `owner_id` 和 RLS。网站记录与文件元数据不得放入同一张通用资源表或 JSON 字段。

### 5.1 常用网站表

#### `resource_links`

- `id uuid primary key`
- `owner_id uuid not null`
- `name text not null`
- `url text not null`
- `category text not null default ''`
- `note text not null default ''`
- `is_pinned boolean not null default false`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`

建议唯一约束：`(owner_id, url)`；同一网址只保留一条记录，修改通过编辑完成。

### 5.2 工作文件元数据表

#### `resource_files`

- `id uuid primary key`
- `owner_id uuid not null`
- `original_name text not null`
- `normalized_name text not null`
- `category text not null default ''`
- `mime_type text not null`
- `size_bytes bigint not null`
- `storage_bucket text not null`
- `storage_path text not null`
- `uploaded_at timestamptz not null`
- `created_at timestamptz not null`
- `updated_at timestamptz not null`
- 唯一约束：`(owner_id, category, normalized_name)`

约束和服务端校验必须保证：

- `size_bytes > 0 and size_bytes <= 52428800`。
- `normalized_name` 由服务端生成，用于同名判断；展示仍使用 `original_name`。
- `storage_bucket` 只能是私有资源桶，例如 `teacher-resources`。
- `storage_path` 必须以当前 `owner_id` 和 `id` 为路径前缀，禁止客户端指定其他用户路径。
- 文件分类、文件名和对象路径之间的归属一致。

### 5.3 存储和RLS

- `resource_links`、`resource_files` 全部启用RLS，所有读写必须满足 `auth.uid() = owner_id`。
- 存储桶保持私有，不开启公开读取；签名URL只在需要预览或下载时短时生成。
- 浏览器端只能使用 Supabase publishable/anon key，不使用 `service_role` 或 secret key。
- 网站保存只能写入 `resource_links`；文件保存只能写入 `resource_files` 和对应私有对象。
- 数据库和存储操作均需再次验证用户归属，不能只依赖前端传入的 `owner_id`、文件ID或路径。

### 5.4 上传与覆盖的一致性

- 新文件先进入临时对象路径，完成大小、类型、用户归属校验后再写入正式元数据。
- 元数据写入失败时删除临时对象，并保持列表原状。
- 覆盖时先完成新对象上传和数据库引用切换，确认成功后再删除旧对象。
- 旧对象删除失败必须记录为清理错误并阻止显示“覆盖完成”，避免产生无法追踪的孤立对象。
- 手动删除只有在元数据和对象删除均成功后才显示“删除成功”；失败时保留可重试状态。

## 6. 代码结构与接口边界

```text
src/modules/resource-library/
  links/
    domain/
      linkValidation.ts
      linkOrdering.ts
    data/
      resourceLinkRepository.ts
    components/
      LinkList
      LinkEditor
      DeleteLinkConfirm
  files/
    domain/
      fileValidation.ts
      fileNaming.ts
      uploadManifest.ts
    data/
      resourceFileRepository.ts
      resourceStorage.ts
    components/
      FileList
      FileSearchFilter
      UploadManifestPreview
      FilePreview
      OverwriteFileConfirm
      DeleteFileConfirm
  shared/
    resourceSaveState.ts
```

边界规则：

- `links` 不得导入 `files` 的 repository、类型或组件；`files` 不得反向导入 `links`。
- 页面组件不得直接拼接 Supabase 数据库或存储请求。
- 文件类型、大小、URL校验、同名判断和排序使用纯函数或 domain service，便于单元测试。
- 上传清单、编辑草稿和覆盖确认只保留在内存，不写入 `localStorage`、URL或日志。
- 文件列表只读取资源元数据，不读取学生档案、成绩、反馈或其他工作模块数据。

## 7. 交互状态

网站编辑、文件编辑和文件上传分别使用明确状态：

- `clean`：没有未保存修改。
- `dirty`：存在未保存编辑或待确认清单。
- `saving` / `uploading`：正在提交，禁止重复操作。
- `saved` / `uploaded`：最近一次操作成功。
- `error`：操作失败，保留可修正内容并显示失败原因。

关闭编辑、切换标签页、切换分类或离开页面前，如有未保存网站编辑或待上传清单，必须提示确认。已上传文件的云端状态必须明确显示为成功或失败，不能只显示本地完成。

## 8. 实施顺序

1. 建立资源库目录、类型和网站/文件两个子域边界。
2. 新增 `resource_links`、`resource_files` 表，配置RLS、唯一约束和服务端归属校验。
3. 创建私有存储桶和按 `owner_id/file_id` 隔离的对象路径策略。
4. 实现常用网站新增、编辑、置顶、打开和删除。
5. 实现工作文件分类、搜索、筛选、重命名和分类修改。
6. 实现批量选择、清单预览、逐文件上传进度和失败重试。
7. 实现同名逐文件覆盖确认及新旧对象切换清理。
8. 实现PDF/图片/TXT预览和其他格式下载回退。
9. 实现删除确认、未保存提醒和明确的云端状态。
10. 完成跨用户、跨分类、跨标签页和跨模块隔离测试，并验证刷新后数据仍可读取。

不得在本模块实施时顺带修改学生档案、成绩、课表、待办、反馈或备课工作流。

## 9. 验收标准

### 常用网站

- 网站和工作文件显示在两个独立标签页。
- 可保存名称、网址、自定义分类和备注。
- 置顶网站排在上方，其余网站按名称排列。
- 点击网站在新标签页打开，不丢失当前页面编辑状态。
- 网站删除需要二次确认，确认后永久删除。
- 非法网址无法保存。

### 工作文件

- 可批量选择常见办公文件，单文件超过50MB时上传前被拒绝。
- 确认上传前可查看和移除待上传文件。
- 每个文件显示独立上传结果，单个失败不影响其他文件。
- 同分类同名文件逐个询问覆盖，未确认前原文件不变。
- 覆盖成功后旧文件永久删除，覆盖失败保留原文件。
- 支持名称搜索和分类筛选。
- PDF、图片、TXT可网页预览；其他文件无法预览时可下载。
- 删除需要二次确认，成功后数据库和存储对象都被删除。

### 隔离与安全

- 常用网站操作不会改变工作文件；工作文件操作不会改变网站。
- 当前用户无法读取或修改其他用户的资源。
- 文件对象不可通过公开URL直接访问。
- 客户端无法通过伪造用户、文件ID、分类或存储路径实现越权。
- 资源库不读取或写入学生、成绩、课表、待办、反馈或备课数据。
- 刷新页面后，已保存网站和文件元数据仍能正确读取。

## 10. 暂不实施

- 文件夹层级和整文件夹上传
- 多标签体系
- 文件版本历史、回收站和恢复
- 资源分享链接或多人协作
- 音频、视频等大体积文件的专门处理
- 网站访问次数统计
